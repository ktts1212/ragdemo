# 清洗 + 分块链路设计

> 代码：`document/{marker/raw, parser/marker, repair, cleaner, domain, chunk, image, pipeline}`
> 上游：Marker API（`infrastructure/marker`）· 下游：入库链路（见 `入库链路设计.md`）

---

## 一、全链路总览

```text
PDF
 ↓ MarkerClient（HTTP multipart → /api/v1/parse）
Marker Raw JSON（Document Tree）
 ↓ MarkerDocumentParser          ← 【Parser：忠实映射，不做语义猜测】
Parsed AcademicDocument
 ↓ ReadingOrderRepair           ← 【Repair：跨页/跨块句续接，保守】
 ↓ PaperCleaner（13 步）          ← 【Cleaner：语义化】
 ↓ CanonicalDocumentValidator   ← 校验 + 21 个质量指标
Canonical AcademicDocument
 ↓ SectionAwareChunker          ← 【Chunker：Section 边界优先】
AcademicChunk[]（+ ChunkQualityMetrics）
```

**分层原则**（skill）：`Parser 忠实 / Repair 保守 / Cleaner 语义化 / Chunker 不修上游结构`

## 二、领域模型（`document/domain`）

### 2.1 根对象

```text
AcademicDocument { documentId, metadata(PaperMetadata), abstractText, sections[], references[], parserInfo }
PaperMetadata    { title, authors[], affiliations[], keywords[], doi, arxivId, journal, publisher, publicationDate }
Section          { id, sourceBlockId, title, level, ★rawLevel, path[], order, blocks[], children[] }
Reference        { id, rawText, title, authors[], journal, publicationDate, volume, issue, pages, doi, pmid, pmcId, arxivId, url }
ParserInfo       { parserType, parserVersion, structureVersion, parsedAt }
```

- `Section.rawLevel` = **Marker 原始声明的 heading depth**（`section_hierarchy` 条目数），与 `level`（会被编号推断/树重建覆盖）区分开，用作层级纠偏的独立佐证
- `Section.path` 是 **List&lt;String&gt;**（不存拼接串），层级 = path.size()

### 2.2 Block 类型（sealed，8 种）

| Block | 关键字段 | 说明 |
|---|---|---|
| `ParagraphBlock` | id, sourceBlockId, **sourceBlockIds[]**, text, order, pageRange, citations[] | 跨页合并段有多个 sourceBlockIds |
| `ListBlock` | id, sourceBlockId（**单数**）, items[], order, pageRange | — |
| `FigureBlock` | id, **sourceBlockIds[]**, label, caption, order, pageRange, imageKey, descriptionText | imageKey ≠ base64 |
| `TableBlock` | id, **sourceBlockIds[]**, label, caption, **html**, **content(TSV)**, order, pageRange | html 仅供 metadata |
| `FormulaBlock` | id, sourceBlockId, label, formula, order, pageRange | — |
| `FootnoteBlock` | id, sourceBlockId, text, order, pageRange | — |
| `CaptionBlock` | id, sourceBlockId, text, order, pageRange | orphan 题注 |
| `NoiseBlock` | id, sourceBlockId, text, order, pageRange, noiseType | HEADER/FOOTER |

> 注意：provenance 字段**不统一**（3 个有复数 `sourceBlockIds`、5 个只有单数），Chunker 用 `BlockProvenance` 归一化。

## 三、Parser 层（`marker/raw` + `parser/marker`）

### 3.1 Marker block_type → 领域映射（`MarkerDocumentParser.traverse`）

| Marker block_type | 处理 |
|---|---|
| `Document` | 递归 children |
| `Page` | `pageTracker.enterPage()` + 递归 |
| `SectionHeader` | `sectionBuilder.openSection()`（开新 Section） |
| `Text` | → `ParagraphBlock` |
| `Figure` / `Picture` / `Diagram` | → `FigureBlock`（三者同类） |
| `Table` | → `TableBlock` |
| `Caption` | → `CaptionBlock`（**不猜测归属**，交给 Cleaner） |
| `List` / `ListGroup` | → `ListBlock`（ListGroup 的 ListItem 收进 items[]） |
| `ListItem` | → `ParagraphBlock` |
| `TableGroup` / `FigureGroup` | **纯包装容器** → 递归 children |
| `Equation` | → `FormulaBlock` |
| `Footnote` | → `FootnoteBlock` |
| `PageHeader` / `PageFooter` | → `NoiseBlock`（noiseType 标记） |
| `Reference` | → `ParagraphBlock`（后续由 `ReferenceExtractor` 归入 references[]） |
| 未知类型 | **不中断**：warning + 递归 children（不丢内容） |

硬失败仅 3 种：顶层非 `Document` / children 为空 / JSON 无法反序列化。

### 3.2 Section 骨架（`MarkerSectionBuilder`）

```text
depth = resolveDepth(title, section_hierarchy)
  ① 优先「标题编号」：I./III.→1 · A.→2 · A.1→3 · 2.1→2 · 3.2.1→3 · 1.→1
     （单字符罗马 I./V./C. 仅当后续标题全大写才判为一级，避免把 "C. Dataset" 误判）
  ② 无编号 → 回退 section_hierarchy.size()
rawLevel = section_hierarchy.size()          ← 独立保留 Marker 原始意见
栈：弹出所有 size >= depth 的 Section → path = 栈中祖先标题链 + 自身标题
```

不出现 SectionHeader 时的正文块 → 创建 `title=null` 的无标题容器兜底（**不允许正文丢失**）。

### 3.3 文本与图片（`MarkerTextExtractor` / `MarkerBlockMapper`）

- Jsoup 解析；**保留含 DOI 的 `<a href>`**（可见文本常被截断，如 `href="...10.1038/xxx">https://doi.org/1</a>`）
- 块级元素（p/div/li/h1-6/tr）前置换行，避免段落粘连；空白归一
- `extractTableText(html)` → **TSV**（row `\n`、cell `\t`），不 flatten 成一句话
- `extractListItems(html)` → `<li>` 文本
- **图片外部化**：base64 → decode → `FigureImageStorage.store(...)` → `imageKey`；**base64 绝不进入领域模型**

## 四、ReadingOrderRepair（`document/repair`）

**目的**：修复 Marker 因分栏/跨页把**一个自然段切成多块**的问题。

**合并规则**（循环直到无变化）：

```text
左块 L 末尾无终止标点（.!?:;）且长度 >= CONTINUATION_MIN_LENGTH(20)
  → 向后扫描，跳过最多 maxSkipBlocks(8) 个「透明块」（Figure/Table/Caption/Formula/Footnote/Noise…）
  → 找到右块 R，且 R 首字母小写（不像新句开头）
  → 合并 L + R：
       · 文本拼接
       · pageRange 延展
       · sourceBlockIds 合并（这正是跨页段 provenance 的来源）
       · citations 合并
  → ★只删除被合并的块 R 与透明 NoiseBlock；【保留】中间穿插的 Figure/Table/Caption/Formula/Footnote
```

> **关键 bug 修复**：原实现 `for (k=j; k>i; k--) blocks.remove(k)` 会**连带删掉中间的图表**。
> 已改为只删 B 与 NoiseBlock ⇒ 目标论文 tables **3 → 6** 恢复。

**配置**（`application.yml: rag.repair.*`）：`max-skip-blocks=8` · `transparent-noise-enabled=true` · `figure-association-enabled=true`
**产出**：`ReadingOrderRepairAudit[]`（供 metrics.repairCount 与人工审计）
**辅助**：`FigureAssociatedTextDetector`（判断右块是否"图内说明文字"，避免误合）

## 五、PaperCleaner —— 13 步管道（`document/cleaner`）

```text
1  FrontMatterPreScan         只观察：在删页眉页脚【之前】收集 DOI/标题/作者/单位/关键词候选
                              ★必须在 HeaderFooterCleaner 之前，否则 PageFooter 里的 DOI 会被先删
2  HeaderFooterCleaner        删除 NoiseBlock（页眉页脚等）
3  FrontMatterCleaner         A.Title（含尾部噪声清洗，如去掉尾部 "OPEN"）B.Authors C.Affiliations
                              D.Keywords E.DOI —— 均「提取成功后才 consume」，失败不删
4  AbstractRecovery           三条路径：① 标题式（Abstract 标题）② 内联式（Abstract—…）③ 位置式
5  CaptionRecovery            双向关联（caption 在图前/图后）+ 类型约束（Figure caption ≠ Table caption）
                              跳过空白/极短(<40)块，避免串图
6  ReferenceExtractor         标题式 / 内容特征式；配合 ReferenceItemSplitter 拆分被合并的多条文献
7  BackMatterClassifier       REMOVE / KEEP（Acknowledgments、Competing interests 等按策略处理）
8  SectionHierarchyNormalizer 标题归一 + 层级告警 + 保守纠偏（Rule A 明显断层修复）+ level/path 一致化
9  SectionHierarchyRepair     ★编号同深度却被父子化 → 平级（skill §5.2）+ ★A2 子比父更浅 → 挂回编号前缀父节
10 MajorAnchorReparenting     ★空孤儿锚点被错嵌在锚点下 → 提为 root 并收编其后同级（skill §4 收敛版）
11 FloatBlockSectionReassigner★Figure/Table 浮动归属：优先「正文显式引用」而非物理位置（skill §6）
12 EmptyContentCleaner        删空段落/空 caption/空 list/空 section；
                              ★标题命中主章节锚点的空 section【保留】（否则 Methods 这种标题会丢）
13 CanonicalDocumentValidator 校验（errors/warnings）+ 21 个质量指标
```

### 5.1 结构修复的三个专项（#9/#10/#11）

**① §5.2 编号同级纠偏（`SectionHierarchyRepair`）**

```text
触发：父子【都有编号】且【编号深度完全相同】→ 子提为父的同级
判据：编号是文档自带的层级声明（不依赖命名、不依赖 rawLevel）
A2（同规则扩展）：子编号比父更浅 → 挂回「编号前缀对应的父节」
      "4.6" → 找编号为 "4" 的 section    "4.4.6" → 找 "4.4"
兜底：找不到目标 / 目标在自身子树内 → 不动 + 告警
编号解析：HeadingNumbering（含单字符罗马歧义消解：仅后续标题全大写才判罗马）
```

**② §4 主章节锚点重挂（`MajorAnchorReparenting`）**

```text
触发 4 条全满足：① 标题命中主章节锚点 ② 该 section 无 block 且无子节点（空孤儿）
                ③ 其父也是锚点 ④ 双方都有 rawLevel ⑤ 存在可收编同级
收编边界 = 语义边界（遇下一个锚点标题停）+ Marker 佐证（rawLevel 相同，不同即停）
实测：Methods（原 Discussion 的子节）→ 提升为 root，收编 Datasets / Pre-processing
```

**③ §6 浮动归属（`FloatBlockSectionReassigner`）**

```text
编号解析 FloatIdentifiers：label 优先、caption 兜底 → FIGURE:4 / TABLE:S3（支持 Fig./Figure/Fig S2）
索引：扫描 PARAGRAPH/LIST 正文里的引用（含「定义性引用」判定：shown in / see Table / illustrated in…）
选择：定义性引用优先 → 否则浮动块【之前最近】的匹配引用
门槛：引用 Section ≠ 当前 Section 且 页距 ≤ 3（无页码时 order 距 ≤ 120）
无引用 / 超距 / 不确定 → 不动（禁止为归零计数强行选择）
只改归属，不动 caption/content/html/sourceBlockIds/pageRange/order
实测：Table 3 归位到 Unified multi-label classification；5 篇共重挂 36 次，页距全部 ≤2
```

**辅助组件**：`MajorSectionAnchors`（锚点归一化：去数字/罗马前缀、去尾部冒号；供 #9/#10/#12 共用）· `SectionTreeUtils`（collect/findParent/rebuildLevelAndPath）· `HeadingNumbering` · `FloatIdentifiers`

### 5.2 Validator（21 个指标）

errors：documentId 空 / sections 空 / base64 残留
warnings：title 空 / 所有 section 无标题 / blockId 重复 / References 滞留正文 / header-footer 残留 / 空 section / orphan caption / front-matter 重复 / level-path 不一致 / affiliation 重复 / root title 不一致 / UNNAMED_NONEMPTY_SECTION
metrics（21 字段）：sectionCount / paragraphCount / figureCount / tableCount / referenceCount / headerFooterRemaining / unnamedSectionCount / emptySectionCount / base64RemainingCount / crossPageMergeCount / repairCount / frontMatterDuplicateCount / orphanCaptionCount / levelPathMismatchCount / duplicateAffiliationCount / rootTitleMismatch / **majorHeadingNestedUnderMajorHeadingCount / sameDepthHeadingParentChildConflictCount / floatReferenceSectionMismatchCount / unresolvedFloatReferenceCount / sectionPathMismatchCount**

## 六、SectionAwareChunker（`document/chunk`）

### 6.1 遍历与不变量

```text
顺序：ABSTRACT → sections（DFS preorder）→ references
不变量：① 不跨 Section 合并（chunk.sectionPath == 内容实际所属 Section 的 path）
        ② 不产空 chunk ③ NOISE 不进 chunk ④ chunkId 稳定（重复 sectionId 时加 #n 后缀）
纯容器 Section（无直属 block）不产 chunk，但仍递归子节点
```

### 6.2 各 BlockType 策略

| BlockType | 策略 |
|---|---|
| `PARAGRAPH` | 同 Section 内按 **targetTokens(700)** 累积为 TEXT；不拆自然段；单段 > max(1000) 才走 句子→硬切（二分） |
| `LIST` | 整体 ≤ max → 一个 LIST；否则按 item 分批；不拆单个 item |
| `FIGURE` | `label+caption+descriptionText`；**caption 与 descriptionText 皆空 → 跳过**（只计 skippedFigure） |
| `TABLE` | `caption(或 label) + content(TSV)`；超长按行分批，**每批重复 caption + 表头行**；html 不进 embeddingText |
| `FORMULA` | 有内容即独立 FORMULA |
| `FOOTNOTE` | 优先并入当前段落缓冲 → 否则并入本 Section 上一个 TEXT → 再否则独立 |
| `CAPTION` | 独立 CAPTION chunk（不丢弃、不在 Chunker 做图文绑定） |
| `MIXED` | 严格判定：缓冲恰好 1 个 paragraph 且 ≤40 token，与紧随结构块合计 ≤ max → MIXED（至多 2 种 blockType） |
| `ABSTRACT` | `abstractText` 单独成 chunk（高价值检索入口） |
| `REFERENCE` | 1 条 → 1 个 REFERENCE chunk（rawText 为唯一必选） |

### 6.3 输出模型与 QA

```text
AcademicChunk：chunkId · documentId · chunkType · sectionId/Title/Path/Level
               content（纯净）· embeddingText（前缀+content，唯一送 embedding）
               blockTypes · sourceBlockIds · overlapBlockIds · startPage/endPage
               tokenCount（★基于 content）· charCount · order · oversized/undersized
               contentHash（embeddingText SHA-256 前 16 位）· titleContext · referenceIds

embeddingText 格式：
  Document: <论文标题>
  Section: <a > b > c>

  Content:
  <content>

预算：target 700 / max 1000 / min 180 / overlap 100（★默认 -disabled；仅同 Section 相邻 TEXT 生效）
QA：ChunkQualityMetrics（28 字段：计数/百分位/不变量/分类/skip/ratio）
```

## 八、已知缺口 / 未验证路径

| # | 项 | 说明 |
|---|---|---|
| 1 | **清洗/分块模块缺少专门的单元回归** | 仓库现有 75 个测试文件，但**没有** Cleaner/Repair/Chunker 的细粒度单测；这条链路只有端到端等价性（`AcademicIngestionGraphEquivalenceTest`）与真实入库验证兜底。改动仍主要靠实测指标 |
| 2 | **Formula / Footnote / 超长段落 / 超长 LIST / 超长 TABLE 路径未触发** | 5 篇真实语料中从未命中（段落 max 仅 382 token ≪ 1000）⇒ 属"未经验证的代码" |
| 3 | `overlap` 默认关闭且未在真实语料验证 | 仅合成场景验证过 |
| 4 | orphan CAPTION 仍未与相邻无 caption 的 Figure 绑定 | 目标论文 1 例（`Fig. 3` ↔ `/page/8/Figure/1`）；属 Cleaner 层面，未做 |
| 5 | SectionHierarchyNormalizer 的 Rule A 会**误重挂** | 5 篇共 13 次重挂中 7 次属"白名单不完备"（3 罗马前缀 + 4 标题变体）⇒ 待修 |
| 6 | 上游字体损坏不改 | `e→The`、`oen→often`、`e?ciency→efficiency`（Marker/Ghostscript 层） |
| 7 | 无「无编号同级纠偏」 | `Pre-processing > Baseline models` 这类（无编号）缺可靠判据 → 只诊断不修 |
| 8 | 图片存储实现选择未落地 | 生产应切 `MinioFigureImageStorage`（当前测试用 `LocalFigureImageStorage`） |
| 9 | token 估算器未标定 | `ceil(chars/4)` 未与 bge-m3 真实分词器对齐 |
| 10 | **历史数据现状** | 下表数字来自 2026-10 的真实语料；2026-10-23 数据库重建后 `document_chunks` 已清空，需在 Marker 可用后重新入库才能复现这些统计 |

## 九、一句话总结

```text
Parser 忠实（block_type→8 类领域块 + section_hierarchy/编号建骨架 + base64 外部化）
Repair 保守（跨页句续接；只删 B 与 NoiseBlock ⇒ 修掉「删中间图表」的 bug）
Cleaner 13 步（PreScan → 页眉页脚 → FrontMatter → Abstract → Caption → Reference → BackMatter
              → 层级归一 → §5.2 编号同级 → §4 锚点重挂 → §6 浮动归属 → 空内容清理 → 校验 21 指标）
Chunker（Section 优先 + BlockType 策略 + token 预算 700/1000/180；content 与 embeddingText 分离）
实测：5 篇全部 valid；598 chunks；硬不变量全绿；入库 126 与离线逐类型一致
缺口：清洗/分块无专门单测、Formula/Footnote/超长路径未触发、Rule A 白名单不完备（7/13 误重挂）
```
