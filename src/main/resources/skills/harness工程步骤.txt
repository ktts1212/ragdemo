Step 2：设计评测问题集 literature_eval.csv
10~30 条，字段：
字段	说明	示例
case_id	编号	1
question	测试问题	ECG-LFM 使用了哪些自监督目标？
reference_answer	参考答案（给 Ragas/Judge 用）	使用 Wav2Vec2 对比损失、MLM 和 CMSC
expected_doc_ids	期望命中的文档 ID（给 Hit@K 用）	12
expected_keywords	期望出现在 contexts 中的关键词	"Wav2Vec2;MLM;CMSC"
question_type	问题类型	method / dataset / result / comparison / limitation / negative
difficulty	难度	easy / medium / hard
Step 3：改造 Java 接口（★ 关键）
当前 POST /api/chat 返回：
{"answer": "...", "sources": [{"docName":"...", "page":3, "score":0.82}]}
需要新增或改造为 POST /api/rag/answer，返回必须包含：
{
  "question": "ECG-LFM 用了哪些自监督目标？",
  "answer": "...",
  "contexts": ["ECG-LFM combines Wav2Vec 2.0 contrastive loss..."],
  "sources": [
    {
      "docId": 12,
      "documentName": "ECG-LFM.pdf",
      "chunkId": 88,
      "score": 0.82
    }
  ],
  "latencyMs": 2341
}
关键新增字段：
字段	来源
contexts	RetrievedChunkDto.content 列表
docId	chunk.documentId
chunkId	chunk.chunkId
latencyMs	记录 chat() 执行时长
最少改动方案：不改 /api/chat，新增一个 /api/rag/answer Controller 方法，直接调 ChatServiceImpl，但返回更丰富的 DTO。
Step 4：写 rag_client.py

# 调用 POST http://localhost:8080/api/rag/answer

Step 5：写 run_eval.py
职责：批量跑，记录所有中间结果。
读取 literature_eval.csv
  → 逐条调 rag_client.py
  → 保存到 run_001/rag_outputs.jsonl
  → 保存到 run_001/rag_outputs.csv
Step 6：写 retrieval_eval.py（★ 最重要）
算确定性指标，不依赖 LLM：
指标	怎么算
Hit@1	top1 的 docId 是否在 expected_doc_ids 中
Hit@3	top3 是否命中
Hit@5	top5 是否命中
MRR	1 / 正确文档首次出现的排名
expected_keyword_hit	contexts 中是否包含 expected_keywords
输出：
- run_001/retrieval_scores.csv
- run_001/failed_cases.csv
Step 7：人工抽检 failed_cases.csv
重点看：
- 检索没命中 → 改 chunk 大小、改 embedding、加 query rewrite
- 排名靠后 → 加 rerank、调 topK
- 上下文噪声 → 降 topK、改 chunk 策略
- 编造答案 → 改 prompt、加引用约束
Step 8：接入 Ragas 或 LLM Judge（后续）
等 Step 6~7 稳定后再加，不是 blocker：
工具	评估什么
Ragas	faithfulness, answer_relevancy, context_precision, context_recall
自定义 LLM Judge	同上，但更可控
Step 9：多版本对比
固定同一批 literature_eval.csv，换配置跑多轮：
run_001_chunk800_top5      → baseline
run_002_chunk500_top5      → 调小 chunk
run_003_chunk800_top10     → 加大 topK
run_004_chunk800_top10_rerank → 加 rerank
每个 run 保存独立目录，对比 summary.json 看哪个配置最好。
