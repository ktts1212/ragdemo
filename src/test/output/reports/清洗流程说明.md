# Marker 解析后文献的清洗说明

> 本文说明**当前代码**里，Marker 解析出的原始 JSON 是怎么一步步被清洗成最终文档的。
> 对应代码：`src/main/java/com/example/ragdemo/document/`

---

## 一、整体链路

```text
PDF
 ↓ MarkerClient                        (HTTP 调用 Marker API，multipart 上传)
Marker 原始 JSON (JsonNode)
 ↓ MarkerDocumentParser                (结构忠实映射：JSON → Java 对象)
Parsed AcademicDocument
 ↓ ReadingOrderRepair                  (跨页续接修复，带 audit)
 ↓ PaperCleaner                        (9 步语义清洗)
Canonical AcademicDocument
 ↓ CanonicalDocumentValidator          (校验 + 质量指标)
```

**核心原则**：`Parser 忠实、Repair 保守、Cleaner 语义化`。
Parser 不修复语义错误；所有语义处理集中在 `PaperCleaner` 的 9 个组件里。

---

## 二、清洗管道编排

`PaperCleaner.clean(document, repairCount)`（`document/cleaner/PaperCleaner.java`）按**固定顺序**调用 9 个组件：

| 顺序 | 组件 | 代码文件 |
|---|---|---|
| 1 | `HeaderFooterCleaner` | `cleaner/HeaderFooterCleaner.java` |
| 2 | `FrontMatterCleaner` | `cleaner/FrontMatterCleaner.java` |
| 3 | `AbstractRecovery` | `cleaner/AbstractRecovery.java` |
| 4 | `CaptionRecovery` | `cleaner/CaptionRecovery.java` |
| 5 | `ReferenceExtractor` | `cleaner/ReferenceExtractor.java` |
| 6 | `BackMatterClassifier` | `cleaner/BackMatterClassifier.java` |
| 7 | `SectionHierarchyNormalizer` | `cleaner/SectionHierarchyNormalizer.java` |
| 8 | `EmptySectionCleaner` | `cleaner/EmptySectionCleaner.java` |
| 9 | `CanonicalDocumentValidator` | `cleaner/CanonicalDocumentValidator.java` |

顺序不可随意调换：例如必须先抽走 Abstract/References，再做层级归一，否则它们会被当成普通 section。

---

## 三、逐步详解（每步的**具体规则**）

### 1. HeaderFooterCleaner — 删除页眉页脚

- **做什么**：遍历所有 Section 的 blocks，删除 `NoiseBlock`。
- **来源**：Parser 把 Marker 的 `PageHeader`/`PageFooter` 映射为 `NoiseBlock`（保留以便追溯），本步负责移除。
- **结果**：`headerFooterRemaining = 0`。

### 2. FrontMatterCleaner — 提取标题/DOI + 删头部噪声

- **选取对象**：**首个非空 Section**（不是固定 `get(0)`——真实语料中 `get(0)` 常是仅含页眉噪声的空 section）。
- **标题提取**（仅当 `metadata.title` 为空）：
  - 若该 section **有标题**：用 `isLikelyPaperTitle()` 判定——长度 8~300、**不匹配编号**（`I.`/`1.`/`A.`）、**不在常见章节名黑名单**（introduction/methods/results/references/…）、不以 `.,;` 结尾 → 则作为论文标题。
  - 若该 section **无标题**：取**首段**，用 `isLikelyTitle()` 判定（长度 ≤300、不以 `.,;` 结尾、不含噪声关键词）→ 作为标题。
- **DOI 提取**：对头部所有段落文本跑正则 `\b(10\.\d{4,9}/[-._;()/:A-Za-z0-9]+)\b`，仅在 `metadata.doi` 为空时填充。
- **删头部噪声行**：删除含 `received:`/`accepted:`/`published:`/`correspondence`/`copyright`/`all rights reserved`/`license`/`creative commons` 等关键词的段落。

### 3. AbstractRecovery — 抽取摘要

两条路径，命中一条即返回：

- **路径 1（标题式）**：找 `title == "abstract"` 或 `"summary"` 的 Section，取其所有 `ParagraphBlock` 文本，用 `\n\n` 连接写入 `abstractText`，然后**删除该 Section**（避免与正文重复）。
- **路径 2（内联式，真实语料常见）**：扫描所有段落，匹配正则 `(?is)^\s*abstract\s*[:：—–\-.]\s*(.+)$`（即文本以 `Abstract—`/`Abstract:` 等开头），且剩余内容长度 ≥ 50 → 写入 `abstractText`，**从正文移除该段落**。
- 已有 `abstractText` 时不覆盖。

### 4. CaptionRecovery — 图表题注关联

- **做什么**：遍历每个 Section 的 blocks；遇到 `CaptionBlock` 时，**向前**扫描找最近的 `Figure`/`Table`。
- **停止条件**：遇到 `ParagraphBlock` 立即停止（不跨段落）；遇到的第一个 Figure/Table 即目标。
- **关联动作**：把 caption 文本追加到目标的 `caption`；把 caption 的 `sourceBlockId` 追加到目标的 `sourceBlockIds`（可追溯）；然后**移除**该独立 `CaptionBlock`。
- **找不到目标**时：保留该 `CaptionBlock`（不丢信息）。

### 5. ReferenceExtractor — 抽取参考文献

两条路径：

- **路径 1（标题式）**：找 `title ∈ {references, bibliography, literature cited, works cited}` 的 Section，取其 List 条目与段落作为候选；提取后**删除该 Section**。
- **路径 2（内容特征式）**：扫描所有 `ListBlock`，若**条目数 ≥ 3** 且**多数条目**（≥ max(2, 半数)）满足 `looksLikeReference()` 则判为参考文献列表。
  - `looksLikeReference(text)`：长度 ≥ 25 且含（4 位年份 `(19|20)\d{2}` | `et al` | DOI | 行首编号 `[n]`/`(n)`/`n.`）。
- **单条构建**：剥离行首编号 → 提取 DOI、年份 → 生成 `Reference(id="ref-{编号或序号}", rawText=原文, doi, publicationDate.year)`。**不猜测 title**（保守，留 null）。
- **正文清理**：提取后把这些条目**从原列表中移除**；非参考文献条目（如续接正文）保留；列表清空则移除该 `ListBlock`。

### 6. BackMatterClassifier — 尾部元信息分类

按 Section 标题（小写、压缩空白后）匹配：

- **REMOVE（移除整个 section）**：`publisher note` / `license` / `reprints` / `rights and permissions` / `peer review` / `additional information` / `author information` / `supplementary information` / `about the authors` / `open access` / `terms of use`。
- **KEEP（保留）**：`data availability` / `code availability` / `ethics` / `acknowledgements` / `author contributions` / `funding` / `competing interests` / `conflict of interest` / `supplementary material`。
- 其余 → 非 back matter，不动。
- 匹配上限：仅当标题长度 ≤ 80 时参与判定。

### 7. SectionHierarchyNormalizer — 标题归一

- 标题空白归一（`\s+` → 单空格）；标题全空白 → 置 `null`。
- 标题原含换行 → 归并为单行，并记录 warning（疑似 Marker 把两个标题合并进一个 SectionHeader）。
- `path` 为 null → 置空列表；`level` 为 null 或 < 1 → 置 1。
- **不做**：不自己"理解论文"发明 section（skill 明确禁止）。

### 8. EmptySectionCleaner — 删除空 section

- 递归删除"既无 block 又无子节点"的 Section。

### 9. CanonicalDocumentValidator — 校验 + 指标

**硬校验（errors）**：
- `documentId` 为空
- `sections` 为空
- 领域模型残留 base64（Figure 的 `imageKey` 或 Table 的 `html` 含 `base64`/`data:image`）

**软校验（warnings）**：
- `title` 为空
- 所有 section title 均为空
- blockId 重复
- block 页码非法（start < 1，或 start > end）
- 仍有 header/footer 残留（NoiseBlock > 0）
- 仍有空 section
- References 仍滞留在正文 sections

**质量指标（`DocumentQualityMetrics`）**：
`sectionCount` / `paragraphCount` / `figureCount` / `tableCount` / `referenceCount` /
`headerFooterRemaining` / `unnamedSectionCount` / `emptySectionCount` /
`base64RemainingCount` / `crossPageMergeCount` / `repairCount`

## 四、关键数据结构

| 类型 | 作用 |
|---|---|
| `AcademicDocument` | 根对象：`documentId` / `metadata` / `abstractText` / `sections` / `references` / `parserInfo` |
| `Section` | `id` / `sourceBlockId` / `title` / `level` / `path` / `order` / `blocks` / `children` |
| `DocumentBlock`（sealed） | 8 种：`ParagraphBlock` / `FigureBlock` / `TableBlock` / `FormulaBlock` / `ListBlock` / `CaptionBlock` / `FootnoteBlock` / `NoiseBlock` |
| `Reference` | `id` / `rawText`（必留）/ `doi` / `publicationDate` 等 |
| `ValidationResult` | `errors` / `warnings` / `metrics` |
| `CleaningResult` | `document` / `warnings` / `validation` |

**可追溯性**：每个 block 保留 `sourceBlockId`（Marker 原始 id，形如 `/page/3/Text/12`）；
跨页合并产生 `ReadingOrderRepairAudit`；图片 base64 经 `FigureImageStorage` 外部化，领域模型只留 `imageKey`。

---

## 五、容错原则

**硬失败**（Parser 层抛 `MarkerDocumentParseException`）：
- 顶层 `block_type` 不是 `Document`
- `children` 为空
- JSON 无法映射

**不硬失败**（只 warning / 记录，继续处理）：
- 未知 `block_type`（**递归子块**，避免丢内容）
- 没有 Abstract / References / Figure
- section hierarchy 不完整
- Marker 返回空文档（所有 Page 无内容）→ 记 error 日志，Validator 标记 `valid=false`

## 六、当前已知未做好 / 未做的事

| 项 | 现状 |
|---|---|
| **表注前置关联** | `CaptionRecovery` 只向**前**扫描；题注出现在表格**之前**时无法关联（如 "TABLE II:" 在表上方） |
| **References 拆分** | Marker 会把多条参考文献合并进一个 ListItem；当前不按编号拆分 |
| **空段落过滤** | 未过滤 `text = ""` 的 `ParagraphBlock` |
| **Abstract 字母间隔** | "A B S T R A C T" 这类字母间隔标题未被识别 |
| **无编号标题层级** | 无编号标题回退到 Marker 的 `section_hierarchy` 深度，可能把正文挂到论文标题下（如 Temporal 那篇） |
