> 本文说明本轮**结构修复**做了什么、依据什么规则、验证结果如何，以及**哪些仍未修、为什么**。
> 对应代码：`src/main/java/com/example/ragdemo/document/cleaner/`
> 依据 Skill：`src/main/resources/skills/canonical_section_float_repair_skill.md`
> 上游链路见同目录 `清洗流程说明.md`、`分块流程说明.md`

## 一、问题背景（含硬证据）

用目标论文 `Toward robust automated cardiovascular arrhythmia detection ...` 逐层验证，确认 skill 声称的问题
**部分存在，但根因与 skill 的假设不同**。

### 1.1 Figure/Table 浮动归属错位 —— 确实存在 ✅

```text
正文（Unified multi-label classification）："From the results in Table 3 the difference in AUROC score ..."
实际归属：Table 3 物理落在 STEMI binary classification
```

### 1.2 "Methods 被错嵌进 Discussion" —— 根因不是嵌套错，而是标题被删 ❌

Marker 原始 JSON 中标题**是存在的**：

```text
[/page/11/SectionHeader/1] depth=2 | Methods          ← 原始 JSON 里存在
[/page/11/SectionHeader/2] depth=2 | Datasets
[/page/11/SectionHeader/4] depth=2 | Pre-processing
[/page/11/SectionHeader/7] depth=3 | Patch segmentation strategy
...
[/page/16/SectionHeader/2] depth=1 | Author contributions
```

真实根因链：

```text
1. Marker 把 Methods / Datasets / Pre-processing 都标成 depth=2（同级）
   → Methods 因此拿不到任何子节点
2. EmptyContentCleaner 把「无 block 且无子节点」的 Methods 当空 section 删除
   → Methods 标题彻底丢失
3. Datasets / Pre-processing 留在 Discussion 下
   → sectionPath = ["Discussion", "Datasets"]  ← 错误章节语义被注入 embedding
```

即：**这是「空 section 被误删」的数据丢失问题，而不是层级重挂问题**。
因此 skill §4 的 Rule 4（主标题 root reset）**没有靶子**，无法达成它承诺的修复。

## 二、本轮执行的三项

按既定默认方案：**①(c) audit 抽查 → ②A 空锚点保留 → ③ 补 5 个 §9 指标**。

### ②A 空主章节 Section 不再删除

**新增** `MajorSectionAnchors`（`document/cleaner/MajorSectionAnchors.java`）

```text
归一化（skill §4.2）：lowercase → trim → 空白折叠 → 去数字前缀 → 去尾部冒号
另兼容"仅保留字母"的宽松形式，避免相比既有实现出现行为回退
锚点集 = 既有主章节集 ∪ skill §4.2 canonical 列表
        （新增 methodology / supplementary material）
```

**修改**

| 文件 | 改动 |
|---|---|
| `EmptyContentCleaner` | 递归删除空 section 时，**标题命中锚点的一律保留**；并加注释说明为何不能删 |
| `SectionHierarchyNormalizer` | 原私有 `MAIN_SECTION_NAMES` 与 `isMainSection` 改为共用 `MajorSectionAnchors`（消除重复定义） |

**效果（目标论文）**

```text
sections 35 → 36          ← Methods 保住了
新增告警 EMPTY_ANCHOR_SECTION_KEPT: Methods
```

### ③ 补 5 个 skill §9 Validator 指标

`DocumentQualityMetrics` 新增 5 个字段，`CanonicalDocumentValidator` **独立重新计算**
（不复用修复组件的计数，构成交叉验证）：

| 指标 | 定义 | 5 篇实测 |
|---|---|---|
| `majorHeadingNestedUnderMajorHeadingCount` | 主章节锚点嵌在另一主章节锚点之下 | Toward robust **1**（Methods under Discussion），其余 0 |
| `sameDepthHeadingParentChildConflictCount` | 子标题编号层级 ≤ 父标题编号层级 | Poly-Window **2**、LEARNING GENERAL **7**，其余 0 |
| `floatReferenceSectionMismatchCount` | 有正文引用，但**当前所属 Section 内无任何引用** | 全 0 |
| `unresolvedFloatReferenceCount` | 有编号但正文完全没有引用的浮动块 | Hierarchical 5 / JAMC 3 / LEARNING 1 / 其余 0 |
| `sectionPathMismatchCount` | `path` 末元素 ≠ `title` | 全 0 |

外加告警 `EMPTY_ANCHOR_SECTION_KEPT: <title>`（空锚点被刻意保留，使其可观测）。

所有指标只作 **warning**，不 hard fail（符合 skill §9）。

**交叉验证结果**：`unresolvedFloatReferenceCount` 与 `FloatBlockSectionReassigner` 自己的
`unresolved` 计数**完全一致**（5 / 3 / 0 / 1 / 0）—— 两套独立实现互证。

## 三、Figure/Table 浮动归属修复（Phase 3）

**新增** `FloatBlockSectionReassigner`（`document/cleaner/`）+ `FloatIdentifiers`（编号识别，共用）

**规则（确定性、可解释、无硬编码）**

```text
1. 编号解析：label 优先、caption 兜底 → FIGURE:4 / TABLE:S3（支持 Fig. 1 / Figure 1 / Fig. S2 / Table S3）
2. 建索引：扫描 PARAGRAPH / LIST 正文，记 {TYPE:N → [引用 Section/块/order/页码/是否定义性]}
3. 选择：定义性引用优先（shown in / see Table / illustrated in …）
          → 否则取浮动块【之前最近】的匹配引用
4. 门槛：引用 Section ≠ 当前 Section  且  页距 ≤ 3（无页码时 order 距 ≤ 120）
5. 无引用 / 超距 / 不确定 → 不移动（禁止为归零计数强行选择）
6. 移动只改归属：caption / content / html / sourceBlockIds / pageRange / order 一律不动
```

**接入点**：`PaperCleaner` 第 9 步 —— 必须在 `SectionHierarchyNormalizer`（稳定树）之后、
`EmptyContentCleaner` 之前（符合 skill §7）。

**验收（目标论文）**

```text
Table 3  → Unified multi-label classification   ✅ 已归位（原在 STEMI binary classification）
Table 2  → PTB-XL multi-label classification    ✅ 未被误动
Fig. 4   → Baseline models                      ✅ 本就正确，未被误动
```

**5 篇实测**

| 论文 | 有编号浮动块 | 重挂 | 无引用(不动) | 超距(不动) | 移动率 |
|---|---|---|---|---|---|
| Hierarchical Self-Supervised | 18 | 5 | 5 | 1 | 28% |
| JAMC | 18 | 11 | 3 | 0 | 61% |
| Poly-Window | 2 | 2 | 0 | 0 | 100%（样本仅 2） |
| LEARNING GENERAL | 21 | 14 | 1 | 0 | 67% |
| **Toward robust** | 9 | 4 | 0 | 1 | 44% |
| **合计** | **68** | **36** | **9** | **2** | **53%** |

| 5 | skill §5.2 编号同级纠偏 | ✅ **已实现** | 见 `层级纠偏_rawLevel与编号同级修复.md`：LEARNING GENERAL 修复 **7 处真错误**（A.2~A.5 / B.2 / E.2 / E.3）；Poly-Window 原报的 2 处经查为编号解析假阳性，已修正为 0 |

### 两个方向的执行状态

| 方案 | 内容 | 状态 |
|---|---|---|
| **②B** | 锚点标题**收编**其后同级 section，直到下一个锚点 | ✅ **已实现**（收敛版 `MajorAnchorReparenting`，出口条件额外要求 rawLevel 相同） |
| **②C** | `Section` 增加 `rawLevel`（保留 Marker 原始 heading depth） | ✅ **已实现**，并据此完成 §5.2 |

> 实测结论：`rawLevel` **不能**作为"应同级"的正向信号（大量合法父子）。
> 因此 §5.2 由**编号**驱动，`rawLevel` 仅作审计佐证与观测告警；
> 无编号的同类候选对另出诊断报告（`无编号同rawLevel父子对_诊断.md`）交人工判断。

## 六、遗留风险

1. **移动率 53% 偏高**：所有移动页距 ≤2、规则内合规，但风险模式是
   *"前文某段定义性引用了属于后文的图"* → 图被贪心拉走。
   → 请人工抽查 `浮动归属修复_audit_抽查.md`（重点看 `reason=nearest-preceding-reference` 的条目）。
   可选收紧：要求「定义性引用 **且** 页距 ≤1」，或「浮动块紧邻 Section 边界」才移。
2. **空锚点 section 会以空节点形式留在树里**（如 `Conclusions`/`References` 内容被抽走后）：
   无 block → 不产 chunk → 不影响检索；代价是 section 树多 1~N 个空节点。
3. **`undersized` 70~82% / `referenceRatio` 0.29~0.52** 仍存在，属 v1 分块设计决定（见 `分块流程说明.md`）。
4. 未覆盖路径：超长段落/LIST/TABLE 切分在 5 篇真实论文中从未触发，仅由合成单测覆盖。
