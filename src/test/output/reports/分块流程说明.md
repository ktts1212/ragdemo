# Canonical 文档的 SectionAwareChunker 分块说明

> 本文说明**当前代码**里，清洗后的 Canonical `AcademicDocument` 是如何被切成检索 chunk 的。
> 对应代码：`src/main/java/com/example/ragdemo/document/chunk/`
> 上游清洗链路见同目录 `清洗流程说明.md`。
> 设计依据：`src/main/resources/skills/section_aware_chunker_design_skill.md`

---

## 一、整体链路

```text
Canonical AcademicDocument              （清洗完成，见 清洗流程说明.md）
 ↓ SectionAwareChunker                  （DFS 遍历 Section 树 + 定稿）
ChunkDraft[]                            （按 BlockType 策略产生的"待定稿 chunk"）
 ↓ 定稿：order / chunkId / embeddingText / tokenCount / contentHash
AcademicChunk[]
 ↓ ChunkQualityReporter                  （度量 + 告警）
ChunkingResult（chunks + warnings + ChunkQualityMetrics）
 ↓
[下一阶段] Embedding → pgvector → Retrieval QA        ← 尚未实施
```

**核心原则（优先级从高到低）**

```text
Section 决定语义边界
> BlockType 决定块内策略
> Paragraph 决定自然文本边界
> Token 预算决定何时切分
```

即：**语义完整性 > 结构完整性 > 长度均衡**。不为了凑齐 token 而跨 Section 合并。

## 二、关键设计决策（含对 skill 原始设计的修正）

| # | 决策 | 原因 |
|---|---|---|
| 1 | **Token 单位显式定义**为 `ceil(chars / 4)`，由 `ChunkTokenEstimator` 抽象、`CharBasedTokenEstimator` 实现（离线、确定性、零网络） | 项目原本**没有任何 tokenizer**，而既有 `rag.chunk.max-chars: 800` 是**字符**口径。skill 通篇用 token 却未定义口径 → 必须显式化，否则预算无意义。后续可换真实分词器 |
| 2 | 预算语义：`targetTokens`(700) 是**累积闸门**，`maxTokens`(1000) 是**单块硬顶**，`minTokens`(180) **只用于 undersized 标记** | skill §6 说 target 是优先目标，但 §9.1 只以 max 为闸门 → 实际永远达不到 target。改为以 target 收口 |
| 3 | **极短 Section v1 不跨 Section 合并**，只标记 `undersized` | skill §8.2 的"并入父 Section"会破坏不变量 `chunk.sectionPath == 内容实际所属 Section.path` |
| 4 | **overlap 默认关闭**（`rag.chunker.overlap-enabled: false`），开启时**仅作用于同 Section 内相邻 TEXT chunk** | 结构块重复会污染检索；v1 先关闭便于对比实验 |
| 5 | **参考文献 1 Reference → 1 REFERENCE chunk**，仅做 QA 标记（`referenceChunkRatio`），**不做检索过滤** | 不把几十条文献合成大 chunk；占比过高只告警，过滤留到 v2 |
| 6 | `ChunkType` 在 skill 的 9 类之外**增加 `CAPTION`**（共 10 类） | orphan caption 塞进 TEXT/MIXED 会丢失可追溯性与后续降权能力 |
| 7 | **Figure 必须有 `caption` 或 `descriptionText`**，只有 `label`（如 "Figure 3"）也算空 → 跳过 | 契约要求"caption 与 descriptionText 都为空则不产出文本 chunk"；label 本身无检索价值 |
| 8 | **`chunkId` 唯一性防护**：重复 sectionId 时加确定性后缀 `#2`、`#3`… 并告警 | 领域模型未强制 `Section.id` 唯一，而 `chunkId` 是下游入库 upsert 主键，冲突会**静默丢 chunk** |
| 9 | `sectionPath` **过滤空白段**；纯容器 Section（无直属 block）**不产 chunk** 但仍递归子节点 | 实测存在空标题 Section 与"Results"这类纯容器节点，否则会产空 chunk / 出现 `Discussion >  > X` |
| 10 | `sourceBlockIds` 归一化（复数 → 单数 → id，有序去重）由 `BlockProvenance` 承担，**不改领域模型** | `Paragraph/Figure/Table` 有复数 `sourceBlockIds`，而 `List/Formula/Footnote/Caption/Noise` 只有单数 `sourceBlockId`；改 sealed 类会波及 20+ 调用点 |

## 四、各 BlockType 处理策略

| BlockType | 策略 | 备注 |
|---|---|---|
| `PARAGRAPH` | 同 Section 内按 `targetTokens` 贪心累积为 **TEXT** chunk；**不拆自然段**；单段 > max 才走「句子 → token 硬切（二分）」并按 target 重新打包 | 任何结构块出现前**先 flush** 段落缓冲，保证 TEXT chunk 不横跨图表 |
| `LIST` | 整体 ≤ max → 一个 **LIST** chunk；否则按 item 分批至 target；**不拆单个 item**（除非该 item 自身 > max） | 每个 item 渲染为 `- <item>` |
| `FIGURE` | content = `label + caption + descriptionText`（去空拼接）；**caption 与 descriptionText 皆空 → 不产 chunk，只计数** | `imageKey` 永不进入文本 |
| `TABLE` | content = `caption`（空则 `label`）+ 表格 `content`（TSV）；超长时按 `\n` 切行，**每批都重复 caption + 表头行** | `html` 只留 metadata，永不进文本 |
| `FORMULA` | 有内容即独立 **FORMULA** chunk；空白跳过（v1 刻意不与邻近段落合并） | |
| `FOOTNOTE` | 优先并入当前段落缓冲；否则并入本 Section 上一个 TEXT chunk；都不行才独立 **FOOTNOTE** chunk | 合并前都校验不超过 max |
| `CAPTION`（orphan） | 独立 **CAPTION** chunk，**不丢弃**，也不在 Chunker 内做图文绑定（属 Cleaner 职责） | |
| `NOISE` | **不产 chunk**，只计数 + 告警 `NOISE_BLOCK_REACHED_CHUNKER` | |
| `MIXED` | 严格判定：缓冲中**恰好 1 个** paragraph 且其 token ≤ 40，且与紧随结构块合计 ≤ max → 合并为 MIXED（**至多 2 种 blockType**） | 长前置段落不合并，拆成 TEXT + 结构块 |

**文档级**

| 类型 | 策略 |
|---|---|
| `ABSTRACT` | `abstractText` 非空即产出 1 个 ABSTRACT chunk（sectionId / path 为空）；为空则不产出 |
| `REFERENCE` | 走 `references[]`，1 条 → 1 个 REFERENCE chunk；content = `rawText` +（有值才附）`DOI` / `Year`；rawText 为空则跳过；rawText 自身超长才句子级切分 |

**输出顺序**：`ABSTRACT` → sections（DFS preorder）→ `references`，`order` 从 0 连续递增。

## 五、AcademicChunk 字段语义

| 字段 | 含义 |
|---|---|
| `chunkId` | `documentId:scopeId:localIndex`，**稳定可复现**（不含随机量）；scopeId 冲突时加 `#n` 后缀 |
| `content` | **纯净内容（无前缀）**，展示与统计用 |
| `embeddingText` | **唯一送入 embedding 的字段** = `Document/Section` 前缀 + content |
| `tokenCount` | **基于 content 统计**，避免前缀污染 token 预算 |
| `charCount` | content 字符数 |
| `contentHash` | `embeddingText` 的 SHA-256 前 16 位，用于变更检测（**不参与 chunkId**，保证 ID 稳定） |
| `blockTypes` / `sourceBlockIds` | 原始类型 + 来源 id 并集（有序去重） |
| `overlapBlockIds` | 因 overlap 被重复计入的 block id（仅 TEXT 可能出现） |
| `startPage` / `endPage` | 来源块页码的 min / max；无页码信息时保持 null（**不伪造**） |
| `sectionId` / `sectionTitle` / `sectionPath` / `sectionLevel` | ABSTRACT / REFERENCE 为 null 或空 |
| `order` | 全文档稳定顺序 |
| `oversized` / `undersized` | `tokenCount > maxTokens` / `tokenCount < minTokens` |
| `referenceIds` | 仅 REFERENCE chunk 使用 |

**embeddingText 格式**

```text
Document: <paper title>
Section: <a > b > c>

Content:
<content>
```

标题为空则省略 Document 行；路径段全空白则省略 Section 行；两者都无则直接返回 content。

## 六、Chunk QA 指标

| 指标 | 含义 | 理想值 |
|---|---|---|
| `chunkCount` | chunk 总数 | — |
| `avgTokens` / `p50Tokens` / `p90Tokens` / `maxTokens` / `minTokens` | token 分布（nearest-rank 百分位） | 接近 target |
| `oversizedChunkCount` | 超 max 的 chunk | 0 |
| `undersizedChunkCount` | 低于 min 的 chunk | 不设硬指标（v1 接受） |
| `emptyChunkCount` | content 为空白 | **0** |
| `noiseChunkCount` | 含 NOISE block | **0** |
| `crossSectionChunkCount` | 跨 Section | **0** |
| `splitParagraphCount` | 被强制切分的超长段落 | ≈ 0 |
| 各类型计数 | text / list / figure / table / formula / footnote / caption / mixed / abstract / reference | — |
| `skippedFigureCount` / `skippedTableCount` / `skippedReferenceCount` | 因无有效文本被跳过的块 | 可观测即可 |
| `overlapChunkCount` / `duplicatedSourceBlockCount` | overlap 生效数 / 重复 provenance 的 block 数 | overlap 关闭时均为 0 |
| `referenceChunkRatio` | 参考文献 chunk 占比 | > 0.5 时告警 |
| `sectionCoverageRatio` | 有正文块的 Section 中，成功产出 chunk 的比例 | **1.00**（用于发现"内容消失"） |

## 八、不变量核验（14 条，均以真实数据或单测为证）

| # | 契约 | 结论 | 证据 |
|---|---|---|---|
| 1 | 不跨 Section 合并 | ✅ | 5 篇 `crossSection=0`；`sectionBoundary_isNotCrossed` |
| 2 | BlockType 决定块内策略 | ✅ | 各类型专用 chunker + 分类计数 |
| 3 | 不拆自然段（除非单段 > max） | ✅ | 5 篇 `splitParagraph=0`；双向单测 |
| 4 | 跨页 repaired paragraph 保持整体 | ✅ | Case1=true；`crossPageRepairedParagraph_isNotSplitByPage` |
| 5 | 无空 chunk / 无 NOISE chunk | ✅ | 5 篇 `empty=0 noise=0` |
| 6 | provenance union + 页码 min/max | ✅ | `pageRange_isMinAndMaxAcrossBlocks`、`provenanceUnion_isStableAcrossParagraphs` |
| 7 | `chunkId` 稳定且唯一 | ✅ | 同输入两次一致；`duplicateSectionIds_doNotCollide` |
| 8 | `tokenCount` 基于 content | ✅ | 定稿只用 content；overlap 后重算 |
| 9 | target 闸门 / max 硬顶 / min 仅标记 | ✅ | `paragraphs_accumulateUpToTarget` |
| 10 | overlap 默认关、仅 TEXT | ✅ | `overlap_isDisabledByDefault`、`overlap_neverAppliesToStructuredChunks` |
| 11 | 空 caption+descriptionText 的 Figure 不产 chunk | ✅ | `figureWithoutAnyText_isSkipped`、`figureWithLabelOnly_isSkipped` |
| 12 | html / imageKey 不入文本 | ✅ | 断言不含 `html-only`、`figure-images` |
| 13 | references 独立、1:1、不混入正文 | ✅ | `references_oneChunkPerReference`、`references_areNotMixedIntoBodyChunks`、Case6 |
| 14 | 顺序 ABSTRACT → sections → references | ✅ | `order_isSequential` |

**已排查并排除的疑点**：`embeddingText` 头部 token 未计入 tokenCount（实测 max=685 + 头部 ≈25 = 710 ≪ 1000，且 bge-m3 上限 8192，无风险）；Spring 单例线程安全（全部无状态，`ChunkStatsAccumulator` 每次调用新建）；`crossSectionChunkCount` 无误报（跨页历史 block id 已登记进映射）。

## 九、复核发现的缺陷与修复

复核方式说明：原计划用 Oracle 交叉复核，但 Oracle 后台任务因**模型 ID 解析失败**（`openai/gpt-5.5` → `opencode/gpt-5.5` → `opencode/gemini-3.1-pro` → `opencode/claude-opus-4-7` 连续 4 次 "Model not found"）无法执行，已取消，改为**逐条契约人工核查 + 真实数据验证**。

| 级别 | 问题 | 修复 | 验证 |
|---|---|---|---|
| 🔴 应修 | 领域模型未强制 `Section.id` 唯一，两个同名 section 会产出相同 `chunkId`（如 `doc:dup:0`）；`chunkId` 是下游 upsert 主键 → **静默丢 chunk** | 新增 `uniqueScopeId()`：已用集合 + 确定性后缀 `#2`/`#3` + 告警 | `duplicateSectionIds_doNotCollide` 断言 `["doc:dup:0","doc:dup#2:0"]` 且不重复；真实数据重复 id = 0（防御性） |
| 🟠 偏离契约 | 契约要求「caption 与 descriptionText **都**为空则跳过」，实现成了「三者**全**空才跳过」→ 只有 `label` 的 Figure 会产出约 2 token 的垃圾 chunk | `chunkFigure` 改为 caption 与 descriptionText 皆空即跳过 | `figureWithLabelOnly_isSkipped`；真实数据指标不变（零回归） |
| 🟡 已知近似 | overlap 的 `overlapBlockIds` 用「尾部 id 数 = 总 id 数 − (段落数−1)」近似定位最后一段 | 已注释说明；overlap 默认关闭，仅影响 QA 统计 | — |

**修复后回归**：`mvn test` → **177 tests / 0 failures / 0 errors / 9 skipped**（skipped 为环境依赖项），BUILD SUCCESS。新增分块测试 **44 个**（`SectionAwareChunkerTest` 27 + `ChunkProvenanceTest` 11 + `TableChunkingTest` 6）。

## 十、遗留问题与 v2 建议

1. **`undersized` 占比 70–82%**
   原因：参考文献每条约 45 token（66 条全部低于 180）+ 论文含 26 个叶子 Section（如 "Competing interests" 仅 41 字符 → 最小 chunk 11 token）。
   现状：v1 按设计不跨 Section 合并，只标记；`embeddingText` 的 Section 前缀提供了语义补偿。
   v2 可选杠杆：① 允许在**同一父 Section 下**合并相邻 undersized TEXT chunk（需记录 `mergedChildSectionIds` 以保 provenance）；② 参考文献 chunk 出场检索过滤。

2. **`referenceChunkRatio` 0.29–0.52**（JAMC 0.51、目标论文 0.52 已触发告警）
   现状：v1 只标记不过滤，`chunkType = REFERENCE` 已落到每个 chunk 上。
   v2：检索时默认过滤或降权 REFERENCE。

3. **真实语料未覆盖的路径**：`oversized` 段落切分、超长 LIST、超长 TABLE、FOOTNOTE——5 篇论文中均未触发（段落 max 仅 382 token ≪ 1000）。这些路径**仅由合成单测覆盖**，属"未经验证的代码"，接入更多论文时需复测。

4. **token 估算器待标定**：`ceil(chars/4)` 对符号/数字/公式会略有偏差。接入 embedding 后应用 bge-m3 真实分词器复测并标定 `targetTokens`。
